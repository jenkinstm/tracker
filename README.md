## Стек

React + TypeScript + Vite · Fastify + Prisma · PostgreSQL 16 · Caddy · Docker Compose

Монорепозиторий на pnpm workspaces: `apps/web`, `apps/api`, `packages/shared`.

## Разработка

Node на хосте не нужен — всё живёт в контейнерах.

```bash
docker compose up -d
```

Поднимаются три сервиса: `db` (postgres:16, наружу не публикуется), `api`
(Fastify на 3000, внутри сети) и `web` (Vite на 5173, проксирует `/api` в `api`).
Миграции и сид применяются на старте контейнера `api`.

Проект называется `tracker-dev` — отдельно от продового `tracker`, чтобы
стеки не делили тома и имена контейнеров.

Vite слушает только `127.0.0.1`: сервер смотрит в интернет, а ufw не фильтрует
порты, опубликованные докером. Открыть интерфейс с своей машины:

```bash
ssh -L 5173:127.0.0.1:5173 deploy@fit.profkosm.ru
```

Дальше `http://localhost:5173` в браузере.

Пароль для входа:

```bash
docker compose run --rm --no-deps api pnpm hash-password
```

Скрипт спросит пароль дважды, посчитает argon2id-хеш и запишет его прямо
в `.env` — в терминале и в истории команд хеш не остаётся. Если `SESSION_SECRET`
пуст, он тоже сгенерируется. После этого `docker compose up -d --force-recreate api`.

> Значения в `.env` пишутся **в одинарных кавычках**. Docker Compose интерполирует
> этот файл, и argon2id-хеш вида `$argon2id$v=19$m=...` без кавычек приезжает
> в контейнер выпотрошенным. Скрипт делает это сам, руками — не забывай.

Тесты и типы:

```bash
docker compose run --rm --no-deps api pnpm test
```

```bash
docker compose run --rm --no-deps api pnpm typecheck
```

## Сид продуктов и упражнений

Данные лежат в `apps/api/src/seed/` обычными TypeScript-файлами: `foods.ts`
(313 позиций), `exercises.ts` (54 упражнения), `programs.ts` (три программы).
Их правят руками, генерации в коде нет.

Заливка идемпотентна и выполняется на старте контейнера `api`. Вручную —
после правки файлов данных:

```bash
docker compose run --rm api pnpm db:seed
```

Что попало в базу и находится ли поиском:

```bash
docker compose run --rm api pnpm seed:check
```

КБЖУ указываются на 100 г **готового** продукта (варёная гречка, а не сухая),
углеводы — общие, клетчатка входит в них. Согласованность проверяется тестами:
калорийность сверяется с макросами по коэффициентам Этуотера, так что опечатка
в разряде не проедет молча.

## Профиль и цели

Норма считается по формулам из `docs/context.md`, код — в
`packages/shared/src/nutrition.ts`. Любую цифру можно переопределить руками:
пустое поле в форме означает «считай по формуле», заполненное — ручное
значение (FR-1.3).

Что реально применяется и как это сошлось с расчётом:

```bash
docker compose run --rm api pnpm targets:check
```

## Дневник питания

Поиск идёт по локальной базе, учитывает регистр и раскладку: `uhtxrf` находит
«гречку». Свои продукты ранжируются выше сидовых.

КБЖУ записи — снимок на момент добавления: правка продукта не меняет историю
задним числом.

Проверить путь целиком — поиск, добавление, «недавние», правку, воду:

```bash
docker compose run --rm api pnpm diary:check
```

Скрипт создаёт записи за сегодня и удаляет их за собой.

## Вес

На главном экране показывается сглаженный тренд, а не сырой замер: утренняя
цифра скачет на килограмм от соли и воды. Формулы — в
`packages/shared/src/weight.ts`.

Окна сглаживания и регрессии считаются в **календарных днях**, а не в замерах,
поэтому пропущенные взвешивания не искажают темп.

```bash
docker compose run --rm api pnpm weight:check
```

Скрипт пишет замеры за прошлые даты, проверяет тренд, темп, прогноз и поведение
при разрывах, затем восстанавливает исходные данные.

## Тренировки

Подходы создаются заранее, при старте тренировки, и предзаполняются значениями
прошлого раза для этого упражнения. Тап по строке отмечает подход выполненным —
клавиатура нужна, только если вес изменился.

```bash
docker compose run --rm api pnpm workout:check
```

Скрипт проводит две тренировки подряд и проверяет критерий приёмки №3:
5 упражнений × 4 подхода отмечаются одними тапами, без ввода чисел.
Созданные тренировки удаляются.

## Экспорт и восстановление

Вся история выгружается одним JSON: экран «Данные» или `GET /api/export`.
Справочник продуктов в файл не входит — его восстанавливает сидер, а ссылки
на него переживают восстановление, потому что идентификаторы детерминированные.

```bash
docker compose run --rm api pnpm backup:check
```

Проверяет критерий приёмки №4: выгрузка после восстановления побайтово
совпадает с исходной. Базу возвращает в исходное состояние.

Прод, бэкапы и откат — в `docs/deploy.md`.

## Прочее

Новая миграция после правки `apps/api/prisma/schema.prisma`:

```bash
docker compose run --rm --no-deps api pnpm --filter @tracker/api exec prisma migrate dev --name <имя>
```

Если Node установлен локально, те же `pnpm test`, `pnpm typecheck`
и `pnpm hash-password` работают напрямую из корня.
