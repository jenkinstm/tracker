# RankPulse

Трекер позиций и частотности в Яндексе для SEO-специалиста, который ведёт 5–20 клиентских
сайтов. Закрывает два действия: **собрать частотность** и **снять позиции**.

Google сознательно вынесен за MVP (веха M9): Яндекс закрывается официальным API целиком,
Google не закрывается никак и требует стороннего парсера. Подробности — в `docs/PRD.md`.

## Что уже работает

- Проекты: домен, регион Яндекса, учёт поддоменов, исправление опечаток, расписание.
- Семантика: импорт текстом и файлом (CSV / TSV / TXT / XLSX, в том числе cp1251),
  дедупликация по нормализованной фразе, группы, целевой URL.
- Частотность: сбор через Вордстат с оценкой стоимости до запуска и пропуском свежих снимков.
- Съём позиций: синхронный и отложенный режимы, режим выбирается автоматически по цене.
- Отложенные операции: отдельная таблица со сроком годности, независимый опрашивальщик,
  переотправка просроченных.
- Отчёт: позиция, предыдущая позиция, дельта, частотность, ранжируемый URL и его расхождение
  с целевым; фильтры по группе, динамике и тексту; экспорт CSV и XLSX.
- Метрики: видимость в ТОП-3/10/50, взвешенная по частотности; средняя и медианная позиция.
- Расходы: разбивка по операциям и проектам, месячные лимиты по запросам и по деньгам.
- Расписание: Celery Beat ставит съёмы по времени проекта, разнося проекты по минутам.

| Слой | Технологии |

## Быстрый старт в docker

```bash
cp .env.example .env      # заполните POSTGRES_PASSWORD и SECRET_KEY
make up
make seed                 # демо-проект «Окна-Демо» на 50 фраз
```

Интерфейс — http://localhost:3000, API и Swagger — http://localhost:8000/docs.
Демо-вход: `demo@rankpulse.ru` / `rankpulse123`.

## Запуск без docker

Нужны PostgreSQL 16 и Redis 7 на локальной машине, Python 3.12 и Node 22.

```bash
cp .env.example .env
# в .env замените хосты postgres/redis на localhost

make dev-install          # venv для бэкенда, node_modules для фронтенда
make migrate
make seed
make dev                  # api :8000, worker, beat, frontend :3000
make status               # что запущено
make stop
```

## Провайдеры данных

Из коробки включена **заглушка** (`SERP_PROVIDER=mock`, `WORDSTAT_PROVIDER=mock`):
детерминированная синтетическая выдача, ключей не требует, денег не тратит. Весь путь —
постановка задачи, отложенные операции, опрашивальщик, отчёт — работает на ней целиком.

Для боевых данных нужен один ключ Yandex Search API v2 на оба сервиса:

1. Аккаунт Yandex Cloud / AI Studio с платёжным аккаунтом.
2. Сервисный аккаунт с ролью `search-api.executor` в нужном каталоге.
3. API-ключ этого сервисного аккаунта (показывается один раз) и `folderId` каталога.

```dotenv
SERP_PROVIDER=yandex
WORDSTAT_PROVIDER=yandex
YANDEX_SEARCH_API_KEY=...
YANDEX_CLOUD_FOLDER_ID=b1g...
```

Цены, лимиты и известные грабли интеграции — в `docs/INTEGRATIONS.md`.

## Деньги

| Операция | Ставка | Замечание |
|---|---|---|
| Позиции, отложенный режим | ~30 ₽ / 1000 | режим по умолчанию |
| Позиции, синхронный режим | ~488 ₽ / 1000 | только вручную и только до `SYNC_MAX_KEYWORDS` фраз |
| Частотность (Вордстат) | ~100 ₽ / 1000 | отложенного режима нет, самая дорогая операция |

Оценка показывается пользователю до запуска и пишется в `api_usage_log` по факту.
При исчерпании месячного лимита новые задачи не стартуют.

## Разработка

```bash
make test     # 100 тестов: ядро, провайдеры на моках, импорт, интеграция съёма
make lint     # ruff + mypy + tsc
```

Тесты не ходят в сеть: все HTTP-вызовы замоканы через `respx`. Интеграционные тесты
работают на отдельной базе `rankpulse_test` и пропускаются, если Postgres недоступен.

Правила работы над проектом — в `CLAUDE.md`, вехи — в `docs/ROADMAP.md`,
что сделано — в `PROGRESS.md`.
