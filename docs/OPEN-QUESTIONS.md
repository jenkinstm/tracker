# Открытые вопросы

Claude Code дописывает сюда всё, что нельзя решить без человека или без проверки на реальном API.
Человек отвечает прямо в файле, дата ответа обязательна.

**Область MVP — только Яндекс** (решение 28.08.2026). Вопросы по Google и точной частотности заморожены до вехи M9 и вынесены в конец файла.

## Требует проверки на реальном API

- [x] **Сколько результатов отдаёт один запрос?** 28.08.2026: Яндекс Search API — 100. Google — 10 (параметр `num` отключён Google в сентябре 2025). ТОП-100 в Google = 10 запросов. Смета пересчитана.
- [x] **Время возврата отложенных запросов.** 28.08.2026: норматив 5 минут, обычно ровно столько. На больших пулах часть задач может ждать полчаса и дольше. **Результат хранится 12 часов, потом удаляется безвозвратно.** Ежедневное расписание возможно. Введена таблица `deferred_operations`.
- [x] **Лимит очереди отложенного режима.** 28.08.2026: жёсткого лимита нет. Ограничивают скорость постановки (несколько десятков RPS, дальше `429`) и суточный бюджет каталога.
- [x] **Wordstat тарифицируется?** 28.08.2026: **да.** GetTop и GetDynamics — 100 ₽/1000, GetRegionsDistribution — 250 ₽/1000, GetRegionsTree бесплатно. Только синхронный режим. Смета пересчитана.
- [x] **Параметры опечаток и фильтра.** 28.08.2026: `fix_typo_mode` (`FIX_TYPO_MODE_ON` по умолчанию) и `filter_mode` (`FILTER_MODE_MODERATE` по умолчанию). В REST-клиенте — `fixTypoMode` и `filterMode`. **# VERIFY на первом же вызове:** названия и регистр enum'ов сверить с ответом сервера, документация по ним неполная.
- [x] **Глубина больше 100 в Яндексе.** 28.08.2026: не нужна. Глубина зафиксирована на 100, для Яндекса это всегда один запрос.

- [ ] **Yandex Search API: фактический бесплатный объём** для нового аккаунта — смотреть в консоли Yandex Cloud.
- [x] **Вордстат API: какие поля частотности отдаёт** — 28.08.2026: только базовая (`totalCount`). Операторы и кавычки в Search API v2 не поддерживаются. Точной частотности из этого источника не будет.
- [~] **Чем закрывать `freq_exact`?** Заморожено до M9: решается тем же посредником, что и Google. В MVP — только базовая частотность, в интерфейсе подписана как «широкая».
  Контекст: Подтверждено на живых данных 28.08.2026: у «купить окна» базовая частотность 47 543, из них «купить пластиковые окна» — 16 862 (35%). Базовая частотность завышает трафик кратно. Вариант А — снимать точную частотность через XMLRiver Wordstat (25 ₽ / 1000 страниц, операторы поддерживаются, +250 ₽/мес на 10k фраз). Вариант Б — MVP на базовой частотности, поле остаётся `null`. Отчёт для клиента без точной частотности заметно слабее.

## Продуктовые решения

**Правило по умолчанию: делаем как в Topvisor.** Если поведение Topvisor неизвестно — реализуем отраслевой стандарт, помечаем `# ASSUMPTION:` и сверяемся здесь.

- [x] Поддомены. 28.08.2026, справка Topvisor: настройка есть, рекомендация — указывать основной домен и включать учёт поддоменов, если они есть. Дефолт оставляем `false`, но показываем настройку явно при создании проекта.
- [~] Домен встречается в выдаче дважды — берём лучшую позицию. В справке Topvisor правило явно не описано, но релевантный URL там один на проверку, что этому не противоречит. Оставляем `# ASSUMPTION:`, при случае проверить на живом проекте.
- [x] Исправление опечаток. 28.08.2026: по умолчанию **включено**. Topvisor не рекомендует отключать — поиск сам правит запрос, и пользователи почти никогда не возвращаются к исходному.
- [x] Глубина — свойство проекта или региона? 28.08.2026: **региона внутри ПС**, вместе с типом устройства и языком. Модель данных перестроена, введена таблица `project_targets`.
- [x] Мобильная выдача в MVP? 28.08.2026: **нет.** Колонка `device` заведена заранее, чтобы не мигрировать партиционированную таблицу позже.
- [ ] Сколько реально занимает прогон 10 000 фраз частотности при 5 RPS с паузами — по расчёту около получаса, проверить на M5.
- [x] Глубина по умолчанию 100. 28.08.2026: да. В Яндексе сотня приходит одним запросом, глубина ничего не стоит. Вопрос вернётся на M9 вместе с Google.
