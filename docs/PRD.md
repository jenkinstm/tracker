# PRD — RankPulse MVP

## Задача

SEO-специалист ведёт 5–20 клиентских сайтов. Ему нужно раз в неделю показывать клиенту: какие фразы выросли, какие упали, какая частотность у семантики. Topvisor это умеет, но стоит денег и не настраивается под свои процессы.

MVP закрывает два действия: **собрать частотность** и **снять позиции в Яндексе**.

Google сознательно вынесен за MVP. Причина не только в цене (он давал бы 90% бюджета на данные), а в зависимостях: Яндекс закрывается официальным API целиком, Google не закрывается никак и требует стороннего парсера. Сначала проверяем продукт на источнике, который полностью под контролем.

## Роли

Одна роль — владелец аккаунта. Мультиюзерность, права, шаринг — после MVP.

## Сущности

**Проект** — сайт + расписание + набор целей проверки.
**Цель проверки (target)** — комбинация «поисковая система + регион + тип устройства + глубина». В MVP цель одна: Яндекс, один регион, десктоп, глубина 100. Модель поддерживает много целей, интерфейс MVP — одну.
**Фраза** — поисковый запрос внутри проекта, принадлежит группе.
**Группа** — папка фраз (например «Коммерческие / Москва»).
**Съём (Check Run)** — одна пачка проверок позиций по проекту на конкретную дату.
**Позиция** — место домена проекта по фразе в конкретной ПС на дату съёма.
**Частотность** — снимок данных Вордстата по фразе на дату.

## Сценарии

### С1. Заведение проекта
Пользователь вводит домен, выбирает регион из справочника регионов Яндекса, задаёт глубину проверки и расписание (вручную / раз в неделю / раз в день). Проект создан, счётчик расхода запросов на нуле.

**Глубина в Яндексе почти бесплатна до сотни:** 100 результатов приходят одним запросом, поэтому ТОП-100 стоит столько же, сколько ТОП-10. Ставим 100 по умолчанию и не мучаем пользователя выбором. Выше сотни цена растёт ступенями по 100 результатов; максимум в Яндексе — 250 для десктопа и 50 для мобильной выдачи.

**Расписание по умолчанию — утро.** По исследованию Топвизора, результаты Search API в утренние часы заметно стабильнее вечерних: разброс ТОПов меньше, выбросов меньше. Ставим 08:00 по времени пользователя и разносим проекты по минутам, чтобы не бить в API пачкой.

### С2. Загрузка семантики
Вставка списка фраз текстом (одна на строку) или загрузка CSV/XLSX. Дубли схлопываются, лишние пробелы чистятся, регистр приводится к нижнему. Показывается, сколько фраз добавлено и сколько отброшено как дубли. Опционально — назначение группы при загрузке.

### С3. Сбор частотности

Доступна только базовая частотность: Search API не поддерживает операторы, а сторонний источник точной частотности отложен вместе с Google. В интерфейсе колонка подписывается «Частотность (широкая)» с пояснением при наведении, чтобы никто не принял её за точную. Это осознанное ограничение MVP, а не недоделка.

Кнопка «Собрать частотность» по выбранным фразам или по всему проекту. Перед запуском показывается оценка: сколько запросов к API уйдёт и сколько это стоит.

**Частотность — самая дорогая операция в сервисе:** 100 ₽ за тысячу фраз против 30 ₽ за тысячу проверок позиций. Поэтому: повторный сбор по фразе, у которой уже есть снимок моложе 30 дней, требует подтверждения; по умолчанию собираем только то, чего ещё нет. Задача уходит в очередь, в интерфейсе — прогресс-бар. По каждой фразе сохраняется: базовая частотность, частотность в кавычках (точная), регион, дата снимка. Повторный сбор создаёт новый снимок, старые не затираются.

### С4. Съём позиций
Ручной запуск или по расписанию.

**Два режима вызова Search API, и выбираются они автоматически, а не пользователем:**

| Триггер | Режим | Почему |
|---|---|---|
| Ручной съём до 100 фраз | синхронный | человек ждёт результат на экране |
| Ручной съём свыше 100 фраз | отложенный | 0,49 ₽ против 0,03 ₽ за запрос — разница в 16 раз |
| Съём по расписанию | отложенный | всегда, никто не ждёт |

Отложенный результат готов примерно через 5 минут и **хранится всего 12 часов**. Прогресс съёма в интерфейсе показывает не только «сколько сделано», но и «сколько ждёт ответа», чтобы застрявший опрашивальщик был виден пользователю, а не только в логах.

Сбор частотности всегда синхронный: у Wordstat отложенного режима нет.

Порог 100 вынести в конфиг. Синхронный режим — единственное место, где мы платим дорогую ставку, и делаем это осознанно ради отклика интерфейса на маленьких прогонах.
 Для каждой фразы делается один запрос в ПС на ТОП-100. Из выдачи определяется позиция домена проекта (совпадение по хосту с учётом `www.` и поддоменов — настраивается флагом проекта). Если домена нет в выдаче на заданной глубине — позиция `null`, в отчёте «>100» (или «>N» по глубине проекта).
Если домен встретился в выдаче несколько раз — берём лучшую (наименьшую) позицию, её URL и записываем как релевантный. `# ASSUMPTION:` в справке Topvisor правило явно не описано, но релевантный URL там ровно один на проверку, что согласуется с этим поведением.

**Релевантный URL** — страница, которую поисковая система фактически ранжирует. Берётся из выдачи, вручную не меняется.
**Целевой URL** — страница, которая должна ранжироваться, по мнению оптимизатора. Задаётся на фразе. Расхождение целевого и релевантного показывается в отчёте отдельным флагом: это одна из самых частых причин, по которой фраза не растёт.

**Учёт поддоменов.** Topvisor рекомендует для сайтов с поддоменами указывать основной домен и включать их учёт — тогда позиция определится независимо от того, что ранжируется, а релевантный URL покажет, что именно. Наш дефолт `false`, но при создании проекта настройка показывается явно, а не прячется в расширенных.

**Исправление опечаток — включено по умолчанию.** Topvisor не рекомендует отключать: поиск сам правит «малоко» на «молоко», и пользователи почти никогда не возвращаются к исходному запросу. Проверять позицию по неисправленному запросу — значит мерить выдачу, которую живой человек не видит.
Сырой ТОП-100 сохраняется на 90 дней: это позволяет потом добавить конкурентов без повторного съёма.

### С5. Отчёт по позициям
Таблица: фраза | группа | частотность | позиция сегодня | позиция на предыдущий съём | дельта | URL, который ранжируется.
Фильтры: группа, ПС, диапазон дат, только выросшие / только упавшие / попавшие в ТОП-10.
График: видимость проекта во времени (доля фраз в ТОП-3 / ТОП-10 / ТОП-50, взвешенная по частотности).
Сводка: средняя и медианная позиция по проекту. Показывать обе — медиана устойчива к единичным вылетам, среднее их усиливает.
Экспорт: CSV и XLSX.

### С6. Контроль расхода
Отдельный экран: сколько запросов и на какую сумму потрачено за месяц, разбивка по провайдерам и проектам. Лимит на аккаунт: при превышении новые задачи не стартуют, а показывают предупреждение.

## Нефункциональные требования

- Съём 10 000 фраз в двух ПС завершается за ≤ 2 часа.
- Падение внешнего API не роняет съём: задача ретраится (3 попытки, экспоненциальная задержка), после — помечается `failed` и не блокирует остальные фразы.
- Идемпотентность: повторный запуск съёма за ту же дату по той же фразе не создаёт дубль, а обновляет запись.
- История позиций хранится минимум 2 года.
- Интерфейс на русском. Даты в часовом поясе пользователя, в БД — UTC.

## Метрика успеха MVP

Один реальный проект на 500 фраз ведётся 4 недели подряд без ручного вмешательства, задачи не падают, расход по факту совпадает с предварительной оценкой в пределах 5%.

**Сверять позиции с Topvisor «в позицию» бессмысленно, и это не наш недостаток.** Выдача нестабильна сама по себе: по замерам Топвизора на 100 тысячах проверок, два одновременных обращения к живому SERP дают в среднем совпадение 8 доменов из 10, а в отдельных случаях ТОПы расходятся полностью. Правильная проверка качества — совпадение *тренда*: если фраза выросла у нас, она выросла и в Topvisor. Требовать ±2 позиции — значит требовать невозможного от самого поиска.

## Что после MVP (не делать сейчас)

**Первым делом:** Google (веха M9) и точная частотность через того же стороннего провайдера — обе задачи решаются подключением одного посредника, поэтому идут вместе.

Дальше: несколько регионов и ПС в проекте (модель уже готова, нужен только интерфейс), мобильная выдача, история изменения релевантных URL, фильтр «для взрослых» в настройках ПС, сбор ИИ-ответов из выдачи, кластеризация по выдаче, отслеживание конкурентов из накопленных снимков, история изменения релевантных URL, уведомления в Telegram, публичные отчёты по ссылке, биллинг и тарифы, API для клиентов.
