# CLAUDE.md

Правила работы над RankPulse. Читай вместе с `docs/PRD.md` — там продуктовое ТЗ,
и с `docs/DATA-MODEL.md` — там схема данных.

## Что это

Трекер позиций и частотности для SEO-специалиста, ведущего 5–20 клиентских сайтов.
MVP закрывает два действия: собрать частотность и снять позиции в Яндексе.
Google сознательно вынесен за MVP (веха M9) — см. `docs/ROADMAP.md`.

Перед началом любого блока работ прочитай:
- `docs/PRD.md` — сценарии С1–С6 и нефункциональные требования
- `docs/DATA-MODEL.md` — таблицы, индексы, ключевые запросы
- `docs/INTEGRATIONS.md` — внешние API, цены, известные грабли
- `docs/OPEN-QUESTIONS.md` — что уже решено и с какой датой
- `docs/ROADMAP.md` — порядок вех, что сделано

## Стек

- Монорепозиторий: `backend` (FastAPI), `frontend` (Next.js), `docs`
- Бэк: Python 3.12 + FastAPI + SQLAlchemy 2 (async) + Alembic + Pydantic v2, Celery на Redis,
  httpx + tenacity для внешних вызовов
- Фронт: Next.js 15 App Router + TypeScript, TanStack Query, Tailwind, Recharts
- БД: PostgreSQL 16, партиционирование `positions` и `serp_snapshots` помесячно
- Инфраструктура: docker compose (postgres, redis, api, worker, beat, frontend)

Версии не меняем без обсуждения. Новые зависимости — только если без них решение
заметно хуже, и с объяснением зачем.

## Жёсткие правила

1. **Схема БД — только через `alembic revision`.** Ручной SQL мимо миграций и правки
   в уже применённых миграциях запрещены. Изменение схемы = новая миграция.
2. **Секреты только в `.env`.** В коде, в коммитах, в примерах — никогда.
   Любое новое значение сначала появляется в `.env.example` с пустым значением.
3. **Расчётные функции живут в `backend/app/services` и покрываются тестами.**
   Это нормализация хоста и определение позиции, оценка стоимости, дельта и видимость,
   `last_day_of_period`. Тест обязателен вместе с функцией, не «потом».
   Обязательно проверяй граничные случаи: пустая выдача, домена нет в выдаче, один съём,
   разрывы в датах, деление на ноль, нулевая частотность.
4. **Позиция и релевантный URL денормализованы в `positions` намеренно.**
   Не «исправляй» это на вычисление из `serp_snapshots` на лету: снимки живут 90 дней,
   а история позиций — два года.
5. **Валидация на входе API — схемой Pydantic.** Типы для фронта выводятся из OpenAPI,
   руками не дублируются.
6. **Синхронный режим Search API стоит в 16 раз дороже отложенного.** Запрет на пачки
   больше `SYNC_MAX_KEYWORDS` проверяется в сервисе, а не в интерфейсе.
7. **Отложенный результат живёт 12 часов.** Опрос ведёт отдельная периодическая задача
   по таблице `deferred_operations`, а не воркер, поставивший запрос.
8. **Ничего не выполняй на продовом сервере.** Деплой идёт через CI. Если нужно действие
   на сервере — напиши скрипт и объясни, что он делает.

## Стиль

- Ответы, комментарии и сообщения коммитов — на русском.
- Коммиты: `feat(serp): определение позиции по выдаче (M2)`. Ссылка на веху обязательна.
- Одна веха — одна ветка, ветки от `main`.
- Интерфейс — русский. Даты показываем в часовом поясе пользователя, в БД храним UTC.
- Деньги — целые копейки (`BIGINT`), никаких `float` на суммах.
- Спорные места помечай `# VERIFY:`, догадки о поведении Topvisor — `# ASSUMPTION:`.
- Комментарии в коде — только там, где неочевидно «почему». «Что» видно из кода.

## Как вести работу

- Одна веха — одна сессия — одна ветка. Список вех в `docs/ROADMAP.md`.
- Веха заканчивается работающим приложением, а не «половиной модуля».
- Перед крупной вехой покажи план: какие файлы создаются, какие меняются, какие
  миграции добавляются. Дождись подтверждения.
- После завершения вехи обнови `docs/ROADMAP.md` и `PROGRESS.md`.
- Если требование в ТЗ противоречит реальности или невыполнимо в выбранном стеке —
  скажи об этом прямо, не изобретай молча обходной путь. Вопрос без ответа — в
  `docs/OPEN-QUESTIONS.md`.

## Чего не делать

- Не ходить в реальные внешние API из тестов. Все HTTP-вызовы в CI замоканы.
- Не собирать ассоциации Вордстата в фоне на всю семантику: это тысячи мусорных фраз.
- Не добавлять фразы в проект автоматически из ассоциаций — только по явному действию человека.
- Не расширять функциональность за пределы текущей вехи «раз уж я здесь».
- Не закладывать Google Custom Search JSON API даже как fallback — он закрывается.
